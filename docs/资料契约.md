# 资料契约

下列记录为确定性生成的本地合成资料，不含真实主体信息。不同文件通过标识字段关联，版本、生效时间、缺失状态和回执字段保留原始业务含义。

## 核心文件

| 文件 | 字段 | 记录数 |
| --- | --- | ---: |
| `hourly_demand.csv` | `store_id`, `date`, `hour`, `transactions`, `traffic_count`, `traffic_coverage`, `activity_id` | 150 |
| `staff.csv` | `employee_id`, `store_id`, `role`, `skill`, `contract_hours`, `region` | 54 |
| `availability.csv` | `employee_id`, `date`, `start_hour`, `end_hour`, `availability_state`, `preference` | 100 |
| `shift_plans.csv` | `shift_id`, `store_id`, `date`, `role`, `start_hour`, `end_hour`, `assigned_employee`, `acceptance_state` | 72 |
| `actual_coverage.csv` | `shift_id`, `clocked_minutes`, `task_load`, `service_wait_minutes`, `variance_reason` | 60 |

## 可选文件

| 文件 | 字段 | 记录数 | 用途 |
| --- | --- | ---: | --- |
| `activities.csv` | `activity_id`, `store_id`, `date`, `kind`, `start_hour`, `end_hour`, `uplift`, `note` | 6 | 未来促销/临时闭店，用于调整预测与需求 |
| `budgets.csv` | `region`, `period_start`, `period_end`, `amount`, `currency` | 9 | 区域经理确认的预算区间，用于比较与发布检查 |

`activities.csv` 与 `budgets.csv` 缺失时不会阻断运行：应用会提示"未提供活动/预算"，并跳过相应调整与预算比较。也可用 `--activities`、`--budgets` 指定其他路径。

## 字段语义

### hourly_demand.csv

* `hour`：0–23 的整点；应用把该小时视为 `[hour, hour+1)`。
* `transactions`：该小时成交笔数。缺失表示未知，不做插补。
* `traffic_count`：抽样得到的客流计数。**缺失不等于 0 客流。**
* `traffic_coverage`：客流计数的覆盖比例（0–1）。只有 `> 0` 时，`traffic_count / traffic_coverage` 才作为全量客流估计；`0` 表示该小时未覆盖。
* `activity_id`：历史活动标签。历史资料中的活动编号**不要求**出现在 `activities.csv`；未出现时按提示处理，因为该文件只描述未来计划期活动。

### staff.csv

* `role`：`sales`（销售/收银）、`service`（顾客服务/清洁）、`receiving`（收货）、`food`（食品与安全）。
* `skill`：与岗位对应的技能标签（register/repair/stock/safety）。
* `contract_hours`：每周合同工时上限。
* `region`：区域（R-S/R-W/R-N），用于跨店支援与预算归属。

### availability.csv

* `start_hour` / `end_hour`：可工作窗口。
* `availability_state`：`available`（可用）、`preferred`（优先）、`unavailable`（不可用）。无法识别的值按 `unknown` 处理并告警。
* `preference`：`morning` / `evening` / `none`，用于偏好评分。
* 同一员工同一天可能有多条窗口；没有记录表示"未知"，不等于可上班。

### shift_plans.csv

* `assigned_employee`：指派员工。
* `acceptance_state`：`proposed`（待确认）、`accepted`（已接受）、`declined`（已拒绝）。已接受班次是承诺，任何修订都不能静默删除或改派。
* 导入资料可能包含跨店、岗位不符或超出可用窗口的已确认班次；这些记录保留，并标记为需协商替换。

### actual_coverage.csv

* `clocked_minutes`：实际打卡分钟。缺失表示未知。
* `task_load`：观测到的任务负荷（合成指标）。
* `service_wait_minutes`：顾客服务等待时长。
* `variance_reason`：`absence`（缺勤）、`demand-shift`（需求偏移）、`late-delivery`（到货延迟）。
* 没有记录的班次在回看中为"未知"，不按 0 分钟或 0 等待。

### activities.csv

* `kind`：`promotion`（促销）、`closure`（临时闭店）、`other`。
* `uplift`：促销时段的需求放大比例，例如 `0.25` 表示 +25%；闭店时留空。
* 应用只把活动用于**预测期**；闭店小时不产生岗位需求。

### budgets.csv

* 一行表示一个区域在一段日期内的预算。规划期若与多个区间重叠，会累计这些区间的金额（重复行只计一次）。
* 缺少某区域预算时，发布检查提示"需区域经理确认范围"，而不是假定无限预算。

## 关联与校验

* 门店、员工、班次、活动通过标识字段关联；引用断裂按错误报告。
* `store-without-staff`、`store-without-demand` 是警告，因为门店可能暂时无员工或暂无历史。
* 导入班次与员工门店/岗位/可用性的冲突是警告或提示，不阻断资料读取；但它们会出现在方案的问题清单与发布检查中。
* 数据缺失、待审、争议和未回执均表示状态未知或处理中，不能解释成零值或成功。记录中的模拟日期用于复现跨期关系，不表示真实业务发生。
